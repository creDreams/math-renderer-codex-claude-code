# ADR 0002：以完整助手消息证明公式来源

状态：采用。日期：2026-11-02。

仅在缓冲区搜索 LaTeX 分隔符，会将用户输入、源代码和命令输出混入公式。会话日志有角色和 Markdown 原文，却不能提供终端坐标。单独使用任一来源都不足以决定覆盖位置。

适配器将屏幕中的 Codex 助手标记及两列续行区域组合为候选消息，同时保留每个 UTF-16 字符到字符格的映射。助手完整文本在规范化换行、空白及少量标题/加粗标记后，必须与本地会话记录中的助手消息一致。只有一个相同工作目录的会话能证明这些可见消息时，才映射其中的完整 display math 块。代码围栏和缩进代码不产生候选。重复公式按消息中出现的顺序和不同屏幕坐标处理。

屏幕只提供位置，排版使用对应助手消息的原始 TeX。用户、工具和 reasoning 记录不进入公式依据。原始文本在逻辑缓冲区保留；选择期间隐藏覆盖层。

整个过程没有终端输出订阅或重写，不创建 PTY，不发送消息、不读取认证文件。只读会话扫描有文件数、读取字节、并发数和保留消息数限制。多个会话证据相同、当前目录无法确认、消息超出扫描范围或终端形状变化时，显示原文。

代价是召回率较低：复杂列表、被 Codex 转换成字符画的美元公式，以及被截断的长回答都可能无法匹配。此决定优先保证覆盖区域有可核对的来源，不以猜测补齐。未来的 adapter 可以增加已验证的 Markdown/原生字符公式映射，并保留同样的来源约束。

2026-11-03 更新：Windows UIA 无可靠工作目录，因此在有界候选会话之间按全文唯一匹配；重复消息保留源码。0.2.0-preview.2 针对真实 PPO 回答增加行内数学的确定性 Unicode 等价：每段只接受原文或受支持 TeX 子集的明确显示结果，完整说明、块公式源码与会话唯一性都必须通过。不以删除行内内容或正则通配放宽全文校验；未知命令仍要求原文。

0.2.0-preview.3 更新：Windows 输入区变化时，允许继续显示已验证的公式，但必须核验所有助手候选的完整来源行、结束边界、候选起始行集合、窗格身份、主题和物理矩形保持一致。未匹配候选也属于核验范围，因为它们会影响会话唯一性。继续定期刷新本地会话；worker 失败或 UIA 不可用时撤下覆盖。实际选区仅隐藏与之重叠的公式。

0.2.0-preview.4 更新：Windows 的来源验证可覆盖长回答的可见片段。只读获取可见区域前方的有界 UIA 文本，确认尚未结束的助手标记与消息开头；用完整块公式对齐来源，核验片段两边的全部可见文字，并要求足够的非公式上下文与唯一会话。终端输入区、工具区域或仅有相同公式不足以证明来源。公式被裁切时只处理其余完整块。此变化允许滚动阅读历史长回答，同时保留来源约束；Tabby 的完整消息规则保持原有行为。

0.2.0-preview.5 更新：实际 SSD 终端包含表格规则线和转换后的圆点列表，简化源码回放不能覆盖这些差异。缩进的表格线不再充当回答结束标记；允许顶层 `-` 列表到 `•` 的明确转换，继续核对每项文字，保护公式减号和代码文本。UIA 前方上下文保留以可见起点为结束位置的尾段，避免字符单位与返回长度不一致时漏掉最近角色边界。

0.2.0-preview.6 更新：表格进入可见区域时，允许简单矩形表格从管道语法转换为有序单元格文字及装饰横线；比较每个单元格，代码区保持原样。Codex 自行转换的简单单行块公式可以按已知字符形式核验，完整 LaTeX 块仍与原文精确对应。转换只影响来源证明，不更改终端文本和坐标；未知转换继续保留源码。
