# 产品方向：减少使用者需要做出的改动

更新日期：2026-11-03。

用户希望后续将项目发布到社区。在自动呈现清晰公式的基础上，安装和日常操作应保持简洁，尽量沿用使用者现有的终端与 Codex 使用方式。

## 使用目标

- 尽量在现有终端内工作，优先研究 Windows Terminal；不以安装或更换为 Tabby 作为默认前提。
- 不修改 Codex 程序、模型提示词或项目文件来要求用户配合公式呈现；输入、审批、中断和继续会话照常使用。
- 安装尽量收敛为一次安装和必要的启用步骤。普通使用者不需要克隆仓库、构建源码或逐个安装排版依赖。
- 保留原位自动渲染这一核心功能；另开网页、手动粘贴公式或导出 Markdown 不计为完成该目标。
- 提供简单的启停与卸载方式。无法可靠渲染时保留原文，不能妨碍 agent 的正常使用。
- 首先做清楚 Codex 与已验证终端的支持边界，再扩展到其他 agent 和终端。

保留用户此前提出的原始输入输出流与终端逻辑状态不变的约束。低安装成本不代表允许默认放宽这些要求。如果现有终端的能力不足以同时满足，应先给出证据、可选路线及各自需要用户做出的改动，再讨论取舍。

## 当前版本的定位

`v0.1.0-preview.1` 是已验证的 Tabby 技术原型，证明了公式识别、原位覆盖及保持原始终端交互的可行性。保留其实现和验证记录，复用排版与识别核心；需要更换终端这一成本使它尚不满足上述产品目标。

当前的便携版启动器减少了 Tabby 的安装步骤，但仍然更换了终端应用。不能将它描述为在现有 Windows Terminal 中安装即可生效的插件。

## 下一阶段的验证关口

在继续正式构建新的接入方案前，需要形成可审核的方案，说明：

1. 用户需要安装什么、启用什么，以及每天如何启动 Codex。
2. 终端提供什么能力，插件如何取得公式位置并参与绘制；图片协议支持不能代替对定位、重绘和滚动的验证。
3. 是否改变原始数据流、光标、字符缓冲区或输入处理；有冲突时明确说明，不暗中改为输出代理或另一套 agent 界面。
4. 在真实 Codex 中验证原位公式、持续输出、滚动、窗口缩放、审批和 Ctrl+C；单独打印一张公式图片不足以证明接入可行。
5. 如何安装、停用、升级和卸载，支持哪些已经实测的版本。

接入架构已确定为 Windows UIA 只读观察与原生覆盖窗口，用户已批准构建及自行验证。首版面向本机 Windows Terminal 与原生 Codex，其他终端另行适配。

0.2 进展：已实现 UIA 自动观察、唯一会话校验、离线公式排版与原位呈现，完成真实鼠标、面板/窗口及独立安装包检查。[构建计划](windows-terminal-plan.md)保留决策依据；当前证据及尚未验收的场景见 [Windows 验证](windows-validation.md)。安装后照常启动 `codex`，默认启动器不再打开 Tabby。
