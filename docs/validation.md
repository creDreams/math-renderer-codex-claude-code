## 性能基线

Chrome 中 600 行 × 140 列样本，预热后 60 次扫描与匹配：P50 2.3 ms，P95 6.1 ms；额外 renderer 初始化 11.3 ms，首次分数排版 1.2 ms。1000 次缓存命中平均约 0.0002 ms。这是本机单次记录，后续运行数据保存在 `test-results/browser.json`。本机回归门槛为扫描/匹配 P95 25 ms、首次 SVG 排版 100 ms。

覆盖层在原区域变化时立即清除，约 50 ms 后合并一次绘制；本地会话索引约每两秒刷新。异步读取完成后检查标签页是否仍存活，SVG 排版为同步本地操作，没有跨版本的异步绘制结果。

## 实测边界

本机 Codex 的 `$$...$$` 会先被 Codex 自身转成字符排版，例如分数变成横线与上下行。屏幕此时不再包含原分隔符，插件保留 Codex 已经生成的字符公式。保留 LaTeX 源码的 `\[...\]` 块已实际验证；原始 `$$...$$` 块在独立 xterm 中通过识别测试。不能把这两种宿主行为混为同一种验证。

完整助手消息必须同时出现在当前缓冲区扫描范围和本地会话记录中。复杂 Markdown、过长/截断回答、目录不匹配、重复会话、格式版本变化、原区域空间不足时，保留原文。流式未完成公式不覆盖。当前不读取工具输出或推理作为公式依据。

会话发现只检查最近目录中最多 160 个 rollout 文件，每个最多读取 4 MiB 尾部及元信息，保留最近 80 条助手消息；屏幕扫描限制为视口附近最多 600 行。它不会以最新文件时间代替会话关联。

浏览器测试不是所有真实 PTY 行为的证明；真实宿主测试补充了插件加载和清理、原版 Codex 交互，以及 WebGL 前端下的自动定位。Linux/macOS、其他 Tabby/Codex 版本和 Claude Code 尚未验收。
