# 鲁棒性与回退规则

适用于 Windows 主线 0.2.0-preview.23。目标是完整且有足够来源证据的公式稳定显示；无法确认来源或位置时撤下图像，保留可操作、可复制的终端原文。输入输出路径始终由 Codex 和 Windows Terminal 处理。

## 回归覆盖

| 情况 | 处理和验证 |
| --- | --- |
| 可选行内公式（.18） | 分隔符优先，无标记表达式须通过有界语法与上下文规则。来源证明传递具体出现位置，不以子串相同借用另一处证据；代码、命令、路径、配置等排除，跨物理行、裁切、位置不明、空间不足均回退。新增单行重复位置、组合字符、缓存淘汰再生、分批渲染及原生 IPC 检查，支持范围与桌面验收进度见[行内公式](inline-math.md) |
| 行内图片完整性、邻近软换行（.19） | 禁止一条公式分片成多个 SVG，检查实际操作数与运算符字形。终端将软换行合并时，按 UIA 物理行逐行核对全部原始文字和矩形，尾部空行不抵消一次软换行；不能确认则保留原文。代码反引号即使被终端隐藏也继续保护 |
| 显式块公式环境及混合上下文（.17） | 新增 15 种环境形式及实际 PNG；列表/引用依据 CommonMark 容器范围，内部减号和比较符保留，代码仍排除。多高度逐行扫描组合样式、链接标签、重复代码、引用、列表和裸环境 Markdown 转换。原始 TeX 保持为排版来源，代码不借用转义/强调转换，来源相同可见但不同原文保持歧义。详见[块公式范围](display-math.md) |
| 流式逐字符输出、未闭合分隔符 | 只映射闭合块；未闭合和过长块不吞掉后续完整块；逐字符前缀回归 |
| 滚动、两端裁切、空行、Unicode、重复公式 | 依据完整公式与上下文定位，每个出现位置独立映射；三种视口高度逐行扫描，核对内容和行范围；公式本身裁切时保留源码 |
| 密集公式、短中文说明、只有公式的可见片段 | 使用同一助手区域内已读取的前方正文连同当前视口核验，来源证明不再取决于可见说明是否达到 24 字符；拼接不连续、角色错误或来源歧义仍拒绝。桌面逐行位置测试核对开闭分隔符对应的真实矩形 |
| 相邻 Codex 原生多行字符数学 | 有界解析已知分式、求和上下限、花体字母、字符边框及内部分式、对齐/矩阵/上下方标注，核对字符与行序，不使用任意字符通配。进入视口、从其任意一行裁切、篡改分子/分母/集合/边框/分数线及颠倒行序均有回归；未知转换仍保留严格原文要求 |
| 原生数学含中文、日文、韩文或全角字符 | Unicode 列宽表用于分数线、填充与边框；保持半角片假名、拉丁重音及组合字符的列宽。中英混排在视口两端逐行扫描，含中文的原生公式与 LaTeX 同屏时仍通过来源证明；修改中文、运算或代码内容不能通过核验 |
| 顶层列表、简单矩形表格、标题、粗体/斜体、已知字符数学转换 | 强调可嵌套或跨过行内数学；简单字符块公式接受源码换行。仅接受确定的等价显示；保留每个表格单元格及数学符号；更改任一正文或算子仍拒绝 |
| Markdown 引用链接、自动链接、已解析引用 | 同时接受原有完整链接和只显示标签的确定形式。标签内样式/数学/代码继续按既有规则保护与核对；链接处于视口中时不要求所有邻近公式同时可见。正文/标签/公式变更和错误角色仍拒绝；只有隐藏 URL 不同的相同可见会话保持歧义 |
| 围栏、波浪号围栏、缩进和反引号代码 | 允许 Codex 隐藏 Markdown 分隔符，正文保持精确核对；代码范围随同来源证明传递，引用与真实公式相同的 TeX 也不会被覆盖。不转换代码中的数学、标题或粗体标记，支持跨行和多反引号代码片段 |
| 已易读的 Unicode 与残留脚本的 Codex 字符块 | 前者保留原字体及间距；后者须沿完整来源证明映射原始规范 TeX，完整独占原行后整体绘制。历史使用完整字符公式摘要，避免常见上下标造成候选扩散；摘要仍只用于查找。.22 起，无可见块标签的字符块须开启预览，关闭后拒绝既有证明和缓存图片；有明确标签的块公式继续显示 |
| 行内字号与同时有上下标 | 提高字号上限，利用原行可用高度；保持原字号下限，允许基线在原行内偏移最多行高 15%，上下至少留 1 px。18 / 28 / 40 / 56 px 行高均检查边界。无法满足时保留原文；不扩大区域、遮挡邻文或回收终端字符占位 |
| 小符号、清晰描边与脚标比例（.23） | 优先放大脚标并增强细笔画，保持字形、数学变体和脚标层级。留白包含描边，实际 PNG 检查笔画覆盖；新布局不能变宽，缩放、基线或空间不合适时保留原脚标比例或完整原布局。小字号逗号下标及大 DPI 的基线边界有独立回归，避免原本可显示的公式消失 |
| 新回答默认停留于底部、耗时标记、输入区、邻近滚动 | 独立桌面回归先展示尚未记录的新回答，再追加完整助手记录，要求无需滚动即出现图像；随后追加终端内容、逐行定位并返回原回答末尾，核对完整块数量和 UIA 矩形 |
| 用户输入、工具输出、错误角色、多个相同会话 | 不因出现相同公式就覆盖；缺少角色/说明或不能唯一确定来源时保留源码 |
| 回答完成标记 | 支持耗时及可选的 `• HH:mm[:ss]`、`• Nov 2 at 16:41` 日期时间后缀，单独验证普通说明、非法日期/时间和连续回答；TS 来源校验和 C# 复用均覆盖同一格式 |
| `$$` 与裁切的前方块 | 从同一助手区域前方恢复公式/围栏状态；索引和显示使用一致摘要与位置解析。UIA 查找先验证实际文本，纯美元分隔符不依赖缺失的 `\[` 查找结果 |
| 非法/不支持的 TeX、放不下的公式 | 每个公式单独失败并跳过，其余公式继续排版；失败后下一次正常快照仍可渲染 |
| 连续输入、迟到的 worker 结果 | 一次只分析一个捕获；回包必须与请求 ID 及实际位置一致；输入改变时仅复用全部候选和边界均未变的证明 |
| 流式追加正文和自动滚动 | 等待新核验时，完整连续的已核验助手前缀未变且来源仍新鲜，可保持其中完整可见的公式；追加正文不成为证明，显示结果不能链式续期。自动滚动按真实前文重新定位并移动已有窗口。修改已核验正文/公式/角色、截断块、前缀重复歧义、换窗格/主题/尺寸均拒绝；真实终端逐字及换行阶段分别验证零次撤图 |
| 真实 Codex 状态动画和下一条回答 | 全部候选继续影响完整来源查找，临时保持仅使用 `verifiedRanges`，磁盘索引合并时保留实际核验区域。实心/空心 Working 圆点和未记录的新回答不能成为旧公式证据，也不能借旧证明渲染新公式；明确歧义或拒绝立即生效。UIA 重绘竞态、不完整几何及异常最多重做两次完整捕获，仍失败撤图，不拼接不同捕获或延长有效期。状态动画回放及真实 Codex 连续回答均验证零次撤图；`hiddenReasons` 累计记录短于采样周期的隐藏原因，不含正文 |
| worker 启动失败、退出、卡住、坏响应 | 来源证明 6 秒过期，启动/请求 12 秒无响应重启；协议、JSON、行范围、图片尺寸和数量异常拒绝；关闭时不向阻塞管道同步追加消息 |
| 会话文件追加、不完整 JSONL、文件替换/删除、大日志 | 独立线程建立磁盘偏移索引，增量读取；不完整行不当作证据；UTF-8 跨块、截断、重建、删除和缓存损坏均有回归 |
| 很早的会话/回答、缓存淘汰、快速回看 | 不再限制最近 160 文件/80 回答/4 MiB 尾部；按可见公式查找和核验。原文/图像 LRU 淘汰后仍可重新生成，过时查找取消，热条目提升顺序 |
| 单击、输入、拖选、菜单、窗口/标签/分屏变化 | 未变的公式保持显示；只隐藏与实际选区重叠的公式；前台、几何或来源失效时撤下。以专用 Windows Terminal 桌面脚本验收 |
| 覆盖存在却落到终端后面 | 枚举实际顶层窗口顺序，修复落于当前前台终端后面的覆盖；不依赖固定次数的窗口链遍历。桌面点击后检查层级顺序，状态中的数量不单独作为可见证据 |

## 有界资源

- Windows 会话发现：遍历数字日期目录（最多 3 层）内全部 rollout JSONL；磁盘索引保存偏移和摘要。每个读取块 256 KiB、单个 JSONL 记录最多 8 MiB、单条助手正文最多 1 Mi 个 UTF-16 字符。没有基于历史文件数、消息条数和日志尾部的截断。保留的 Tabby 原型仍使用旧的有界 SessionStore。
- UIA：可见文本和前方上下文各最多 65536 字符、最多 300 个物理行矩形；捕获超过 500 毫秒即不可用。前方上下文读取先有界保留尾部，避免丢失最近的角色边界。
- 公式：每块最多 8192 字符、100 个正文行；默认每次最多 16 张图片，行内预览开启时最多 256 张；单张 PNG 最大 2 MiB、整批最大 12 MiB，源码区域高度最大 4096 像素。行内候选最多 1024 字符、只占一个物理行。超过限制的公式保留源码，已通过的公式继续显示。
- 原生字符排版预测：块源码最多 4096 字符，行内最多 1024，嵌套深度小于 32，布局最多 16 行/256 列，矩阵最多 16 列。嵌套分式等无法保证语义的转换拒绝预测，不影响严格源码对应。
- 缓存：原文 128 项/8 MiB、Markdown 显示推导/代码及容器范围/裸环境显示候选各 64 项/4 MiB、SVG 128 项/16 MiB。PNG 默认 64 项，行内预览开启时 1024 项，均限制 32 MiB。新增行内识别 128 项/8 MiB、不可排版结果 1024 项/256 KiB、几何 1024 项的缓存。容量按保留字符串的 UTF-16 字节估计；读取提升 LRU 顺序。尺寸、主题或缩放变化不会沿用错误图片。公式图像只放在原有源码占据的区域内。详细调度、缓存与失效规则见[历史按需渲染](history-rendering.md)及[行内公式](inline-math.md)。

## 验证边界

自动化入口为 `npm run verify`、`npm run test:windows-core`、`npm run test:windows` 和 `npm run test:windows-package`；实际执行版本及结果见 [Windows 验证](windows-validation.md)。桌面测试只操作具有独立名称和配置目录的自建研究窗口。

这些检查不等于所有环境均已支持。混合 DPI、多显示器、透明背景、管理员终端、WSL/SSH、其他 agent/终端及长期高负载运行仍需专门验收。复杂 Markdown 表格、未知 Codex 字符转换、角色边界超出 UIA 前方范围、超大记录及裁切的公式可能保留源码。上下文压缩不直接决定渲染；来源记录可读取且通过核验才会显示。
