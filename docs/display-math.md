# 块公式识别范围

Windows 主线 `0.2.0-preview.17` 保留原有 `\[...\]`、`$$...$$`，新增完整的显式 LaTeX 显示环境：

| 环境 | 形式 |
| --- | --- |
| 单式 | `equation`、`equation*`、`displaymath` |
| 对齐 | `align`、`align*`、`alignat`、`alignat*`、`flalign`、`flalign*` |
| 多行 | `gather`、`gather*`、`multline`、`multline*` |
| 兼容旧输出 | `eqnarray`、`eqnarray*` |

例如以下内容可以直接识别，不需要再套 `\[` 或 `$$`：

```latex
\begin{align*}
f(x) &= x^2 \\
g(x) &= x+1
\end{align*}
```

`aligned`、`split`、`gathered`、`cases` 和各类矩阵是内部结构，需放在上述环境或原有分隔符内，不能单独作为显示块触发。`alignat` 保留必要的列参数。环境名区分大小写，开闭名称必须匹配；可多行或整块独占同一行，不覆盖与公式同一行的额外说明文字。

## 来源和上下文

候选识别、来源索引及渲染共用规范公式。先确认完整闭合、非代码、助手角色和唯一会话，再将会话中的原始 TeX 交给 MathJax。列表、嵌套列表和引用根据 CommonMark 容器范围识别；只移除实际容器前缀，公式正文中的 `-`、`>` 等保留。反引号、围栏及缩进代码中的示例仍是源码，包括列表和引用内部的代码。

Codex 0.166.0 会把未套分隔符的环境按普通 Markdown 展示，例如将 `\\` 显示为 `\`，或把部分 TeX 下划线解析成强调标记。核对器接受原文和确定的标点转义、强调/反引号标记显示形式，图像始终使用原始 TeX；索引同时记录相应摘要。样式依照 CommonMark 语法树推导，保留引用/列表的物理前缀。不同原文如果产生相同可见内容，仍无法据此区分来源，保持歧义并保留源码。不将任意缺失/改变的数学当作等价形式，代码正文也不使用该转换。

.17 的历史派生索引由 `history-v1` 升为 `history-v2`，使未变的旧会话也重新扫描新增环境；.20 升为 `history-v3`，加入原生字符块的残留脚本摘要，使不含原始分隔符的视口也能查找来源。不改动或迁移 Codex JSONL。首次升级需要后台建索引，之后复用磁盘结果。Markdown 上下文范围及环境显示候选分别用 64 项/4 MiB LRU；上下文只保留偏移和容器类型，不保留语法树。

## 验证和边界

单元及集成回归覆盖全部列出的环境及实际 SVG/PNG、内部结构、代码、上下文、重复公式、流式前缀、闭合错误/注释/转义和历史重建。多高度逐行视口检查组合标题、强调、链接标签、列表、引用、转义行间断行和相同代码示例，独立检查内容与开闭行。

`npm run test:windows-environments` 在独立 Windows Terminal 中回放确定的上下文混排，检查默认底部、来源追加、相邻滚动及返回底部。期望范围来自夹具的完整字面块，不调用生产解析器计算预期坐标。`npm run test:windows-live-environments` 另发一次无工具的真实 Codex 请求，检查正文、列表和引用三种实际显示；`npm run test:windows-live-stream -- --environments` 用两次请求检查环境公式在后续流式回答中的保持。这两项真实测试会消耗模型用量。

显示区域仍为原源码占据的物理行，不重排终端。裁切块、太大/太小的区域、未知显示转换、不支持的 TeX、来源不足或歧义继续保留源码。仅接受本地受限 MathJax 的 `base`/`ams`，不增加宏定义、外部加载或跨公式编号/引用管理。未知环境及行内/无标记表达式未新增识别。

实测结果见 [Windows 验证](windows-validation.md)。
