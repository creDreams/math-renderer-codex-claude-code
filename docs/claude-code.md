# Claude Code 初步适配

版本：0.2.0-preview.30。

启动 Agent Math，在托盘勾选 **行内与无标记公式（预览）**，然后照常在 Windows Terminal 启动 `claude`。现有 Claude 会话可继续使用，切回窗口或滚动后会重新核验，无需重启 Claude 或更换终端。关闭预览后，无标记数学代码块恢复原文；明确标记的块公式继续由基础功能处理。

## 识别范围

- 无语言标记、`text` / `plaintext` 代码块中，可明确解释为数学的表达式及有限的说明文字。
- `math` / `latex` / `tex` 代码块、`\[ ... \]`、`$$ ... $$` 及现有显式块环境。
- 常见 `_`、`^`、`^(i)` 上下标，希腊字母、带上下限的 `Σ`、求和、常见数学函数、集合条件与跨行表达式。
- 序列下标 `y_<t`、`y_≤t`、`y_{<t}`，采样记号 `x~p` / `x∼p`，带上下标的 `Π` / `∏` 乘积，多行连续等式和嵌套脚标。
- 常见激活/归一化/概率函数、Unicode 上下标和带帽字符、导数撇号、绝对值/范数、积分、标准 TeX 分式/根式及可伸缩括号。完整的独立分式、积分、范数或梯度表达式也可识别，不强制附带等号。
- 一个块内以空行分开的公式独立核验和显示，滚动时无需整个回答同时可见。
- 自定义函数如 `sg[...]`、`customMetric(...)` 和命名变量无需加入白名单；复合下标 `y_{i,<t}`、多字母脚标及 `J_GSPO-token` 这样的脚标标签均可转换。未知 Unicode 数学字形尽量按原符号保留。
- 空行后以等号或运算符开始的续行与前一条推导保持整体；独立公式分别处理。一条表达式转换失败时，其他独立表达式仍可显示。
- 偏好关系 `≻` / `≺` / `≽` / `≼`、独立/平行及常见渐近比较，Unicode 与对应 TeX 命令等价；函数参数括号内支持分号，顶层代码语句分号仍拒绝。
- 完整数学表达式后的简短“当、若、否则、单位”等说明，以及明确分隔的 `where` / `if` 等英文说明，按原文作为直立文字混排，不把说明中的单词当成数学变量。块中独立的“其中、说明、where”等说明行保留终端文字，前后完整数学区域分别核验。

数学代码块保留原符号含义：`/` 仍作为斜线，`E` 保留字母，括号指数保留括号。插件不调用模型解释或改写公式。中文集合条件使用本机系统字体，数学字形使用包内字体，全部离线生成。

.30 将数学区域发现与记法转换分开。先根据块内容的数学符号、上下标、结构及邻近数学说明发现候选区域，再转换其中的完整表达式；函数名和变量名不必属于固定词表。普通说明行保留终端文字，损坏或不支持的表达式只保留自身原文。明显程序语法或已标记程序语言的块整体保持原文，避免把程序中的数学尾部误作独立公式。只包含 `foo = bar` 的无上下文代码块仍视为歧义。

`Π`、`Σ` 在带上下标并作为运算符时分别排版为乘积、求和；无上下标时保留希腊字母。`1e-8` 作为科学记数法排版。单个表达式最多 4,096 字符、64 行、20 层嵌套，转换有步数上限；整个块最多 64K 字符、2,048 行，单段混排说明最多 256 字符。无法转换的自定义 TeX 命令保持原文，明确的 `math` / `latex` / `tex` 块继续支持原始 TeX 排版。

历史派生索引升级到 `claude-v5`，首次切入 Claude 时自动重建。候选区域在转换失败时也保留精确原文索引，区域发现不会再被转换器词表阻断；原会话文件不变。正文中的无标签行内公式仍不在本轮扩展范围。

无语言标记不代表一定是数学。程序语言代码块、明显程序、工具结果、用户输入、思考内容与子代理日志均保留原文；数学块中不支持的表达式局部回退。普通正文中的无分隔符行内公式尚未扩展为 Claude 专用识别；这次主要支持数学代码块。

## 来源和显示

本机检查使用 Claude Code 2.1.317。样例中的蓝紫色来自无语言标记代码块的通用代码样式，普通命令也可能同色。识别不依赖固定 RGB 值。

适配器只读 `~/.claude/projects/<project>/<session>.jsonl` 的助手正文；支持以 `CLAUDE_CONFIG_DIR` 指定目录。不会读取凭据或更改 Claude 设置，也不占用 PTY 或终端输入输出。会话结构未知、原文尚未落盘、来源歧义、公式被裁切或原位空间不足时保留原文。

历史使用单独的 SQLite 派生索引，增量扫描文件并校验源文件版本和记录摘要，源码及图片缓存有固定上限。Claude 索引在识别到 Claude 画面后才启动，Codex 继续使用自己的解析和匹配规则。

.26 支持 Claude 自己重绘的历史及底部视图：终端缓冲区可能只有当前可见正文，既没有 `●` 助手标记或屏幕上方的历史文本，也没有置顶问题和导航提示。适配器从底部向上核验输入框及 Claude 模式栏；历史导航提示仍可辅助确认，再独立检索每条完整公式的来源。置顶问题、输入框和浮动控件所在行不作为公式区域，缩进的正文分隔线不会截断后续回答。缺少邻近正文时，只在已确认的 Claude 视图内接受唯一来源的完整表达式。

公式统一使用中性色，不继承代码块或正文的语法着色。深色背景默认浅灰、浅色背景默认深灰，按实际背景保证对比度；同一背景下滚动不会改变公式颜色，也不会因此重新生成不同颜色的图片。此配色适用于原生组件中的 Codex 和 Claude。

窗口通过 UI Automation 只读定位。仅占用公式实际所在行及紧邻的空行，空行不会被两条公式共享，不增加终端行数。鼠标穿透；选区涉及公式时撤下相应图片，复制取得原文。已核验的历史图片可在下一条回答追加时复用；已确认的 Claude 页面不读取无关终端历史，避免状态重绘生成的旧缓冲区文本反复使证明失效。改变公式、来源或窗口身份仍使旧证明失效。

.27 补充 Claude 自绘选区：Claude 的普通鼠标拖选可能只改变文字背景，并不出现在 Windows Terminal 的原生选区接口中。组件同时检查公式所占物理行的背景属性，选区涉及哪条公式就显示哪条的原文；部分选中也撤下该条完整图片，清除选区后复用原图恢复。背景样式不进入助手来源证明或图片身份，避免选区变化重新排版。正文选区、普通移入和单击不主动撤图，不增加全局鼠标钩子，也不截获鼠标或复制操作。Shift 拖选触发的终端原生选区继续支持。

背景检测不依赖固定选区颜色。均匀回答区域只查一次；存在混合背景时才按公式检查，公式区域内其他背景强调也保留原文，避免覆盖原有视觉信息。

无标记数学块贴近视口边缘、少了一行可用空白时，优先保留常规显示排版；若过高，则尝试数学文本样式，把求和上下限放到侧边。公式内容和可读字号下限保持一致，不裁切符号或覆盖正文；两种排版都放不下时仍显示原文。

流式生成需要等待完整数学块和可核验的会话记录；不承诺在 Claude 落盘前显示尚未完成的公式。

## 验证

`tests/claude-adapter.test.ts` 覆盖数学样例转 SVG/PNG、代码与角色排除、未闭合流式块、超过 2,000 种历史/底部视口组合、换行、主题独立性、预览开关、来源歧义、记录增量写入和源文件删除。16 份布局样例由 TypeScript 匹配器和 C# 原生组件共同验证；另检查 4,096 种背景下的配色对比度。合成样例不包含私人会话记录。

`tests/claude-notation.test.ts` 与 `tests/fixtures/claude-common-math.json` 覆盖 54 组常见数学样例的实际 SVG/PNG、480 个序列/采样组合、程序与说明文字反例、源文变化和独立视口。`tests/claude-math-block.test.ts` 另覆盖完整十条 DPO 推导的逐行裁切、实际 PNG、偏好关系含义、数学/程序分号区分、中文/英文混排、CRLF 原文偏移和独立说明行保护。样例中的算法名称只用于测试说明，不参与生产识别。历史测试另验证旧索引遗漏的公式在源文件未改动时重建，并保持精确查询和暖缓存零原文读取。

`tests/claude-region.test.ts` 与 GSPO 数学样例验证六个数学区域的全部八条表达式，包括复合下标、空行续行、自定义函数和带连字符的脚标标签，检查实际可读 PNG 和每个视口切片。另验证坏表达式与相邻公式隔离、转换失败仍建立来源索引、未知 Unicode 字形、文字括号、普通说明、CRLF、未闭合流式块、程序和大小/嵌套限制。

开发诊断可运行 `npm run diagnose:claude -- --source-file answer.md`，只读取明确指定的本地回答文本，报告数学候选、可排版数量及局部失败原因；`--include-source` 可额外输出对应原文。该检查不包含真实终端的几何定位和选区，不会扫描私人会话或发送模型请求。

`npm run test:windows-claude` 使用独立 AgentMathResearch 窗口回放合成 Claude 风格输出，检查实际覆盖窗口、动态状态、下一条回答、选区、主题和滚动；另覆盖没有助手标记的 130 种历史/底部位置与布局组合、导航提示及置顶问题同时消失、底部状态动画和原文改动。去掉紫色语法着色前后，断言公式配色及图片身份完全一致。不会启动 Claude 或调用模型。机器可交互且测试窗口保持前台时执行。

`npm run test:windows-background` 另用独立 Windows Terminal 窗口读取实际 UIA 背景，验证部分选中、跨公式选中、正文选中、跨行、软换行及覆盖空白行。它不切前台、不发送鼠标键盘输入，可单独执行，但不能代替真实鼠标和覆盖窗口的桌面检查。

本轮详细结果记录于 `docs/windows-validation.md`。真实 Claude 模型请求的端到端生成延迟尚未验收；桌面回放不能替代该项测试。
